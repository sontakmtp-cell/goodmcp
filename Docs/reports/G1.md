## 2. Database, tenant và credential

- PostgreSQL thật **18.1**, CPython **3.12.12/Linux**, FastAPI 0.162.0,
  SQLAlchemy 2.1.6, Alembic 1.20.1, psycopg 3.3.6; dependency root `uv.lock` khóa
  phiên bản/hash, image Python/PostgreSQL/Caddy/uv pin digest. Không đổi lock G0.
- `hub_migrator` sở hữu schema/bảng; `hub_runtime` **không owner, superuser,
  BYPASSRLS, CREATE ROLE hoặc CREATE DATABASE**, không được TRUNCATE hay ghi
  membership. API/worker/tests chỉ mount runtime_password. Admin là CLI riêng
  ngắn hạn, không có public route hoặc Docker socket.
- RLS ENABLE + FORCE trên **20 bảng dữ liệu**, gồm identity và các bảng riêng.
  `alembic_version` là metadata migration, không chứa dữ liệu tenant và không bật RLS.
  Private table có workspace_id NOT NULL, UNIQUE(workspace_id,id), parent FK
  composite theo workspace. Actor trong artifact/job cũng phải là membership
  của workspace đó. Audit append-only đối với runtime.
- Context user/workspace đặt bằng `set_config(..., true)` trong transaction.
  Kiểm membership bằng identity trước khi đặt workspace; role lấy từ DB.
  Thiếu context bị deny. Kiểm pool dùng **cùng pg_backend_pid** cho A → B rollback
  → không context; không chỉ tạo connection mới để giả lập isolation.
- Bootstrap tạo một owner/một workspace và scrypt password hash, không in password.
  Chạy lần hai trả cùng owner/workspace, không tạo trùng hoặc đặt lại password.
  Secret ngẫu nhiên ở `.local/secrets`, bị Git ignore; không có password cố định
  trong source/image. File secrets là cơ chế local, không tuyên bố là secret vault.

Mọi route nghiệp vụ HTTP trả 401 cho tới G2, kể cả khi gửi X-User-ID,
X-Workspace-ID hoặc Bearer giả. G1 chỉ kiểm primitive nội bộ với hai tenant giả
trong PostgreSQL; chưa có identity/token/session production. Không dùng Principal
do test tạo bằng code như bằng chứng OAuth đã hoạt động.

Cơ sở chính sách RLS và giới hạn owner/superuser:
[PostgreSQL 18 Row Security](https://www.postgresql.org/docs/18/ddl-rowsecurity.html).
Context transaction-local theo
[set_config](https://www.postgresql.org/docs/18/functions-admin.html).
Secret được mount theo service theo
[Docker Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/).

## 3. Filesystem ArtifactStore

Store gắn với tenant transaction đã kiểm membership. Public descriptor có UUID,
SHA256/bytes/media_type/revision/time, không có storage_key hoặc absolute path.
Namespace server: `workspaces/<workspace UUID>/blobs/<SHA256>`.

Put giới hạn byte, kiểm checksum kỳ vọng, ghi temp, fsync và publish bằng hard link
atomic không overwrite, sau đó insert DB pointer. Hard link cùng volume giữ tính
atomic tương đương mục tiêu publish của contract, đồng thời tránh ghi đè blob
đang được dùng. Key không lấy từ path do client đưa vào.

Read kiểm quyền qua DB trước, kiểm namespace khớp, checksum/size của file và
O_NOFOLLOW cho từng directory/blob. Byte range nội bộ dùng [start,stop), giới hạn
8 MiB; adapter HTTP ở G3 sẽ đổi quy ước range khi cần. Delete kiểm revision và
pin/reference rồi **tombstone**; không xóa vật lý blob. Kiểm thử chặn handle B,
path traversal, UUID giả, metadata key trỏ tenant khác và symlink ra `/etc/passwd`.

Chưa có physical GC, backup snapshot accounting, quota/upload pipeline hoặc
hostile-code sandbox. DB rollback có thể để orphan blob đã publish; giữ để dọn
bằng GC có grace period ở giai đoạn sau, không xóa mù theo path từ client.
Đây là isolation ở DB/core boundary; API trusted có volume toàn store, **chưa phải
runner plugin cách ly filesystem tenant** của G4.
